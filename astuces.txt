### B. La bonne pratique pour vos futures versions
Voici le flux de travail idéal pour publier une nouvelle version (par exemple, la 0.2.0) :

Assurez-vous que votre code est prêt et que tous les changements sont commit.

Mettez à jour le numéro de version dans votre fichier pyproject.toml (ou setup.py).

Faites un commit pour ce changement de version.

Bash

git add pyproject.toml
git commit -m "Bump version to 0.2.0"
Créez le tag sur ce dernier commit.

Bash

git tag -a v0.2.0 -m "Release version 0.2.0"
Envoyez le commit ET le tag sur GitHub.

Bash

git push
git push origin v0.2.0  # Pousse spécifiquement le nouveau tag
Maintenant, construisez votre package et publiez-le sur PyPI.

Bash

python -m build
twine upload dist/*
Enfin, allez sur GitHub pour créer la "Release" associée au tag v0.2.0 en y ajoutant vos notes de version.
